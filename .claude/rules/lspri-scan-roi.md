# LSPRi: scan, ROIs, analysis rules

Moved verbatim from `apps/LSPRi/eva/CLAUDE.md` (2026-11-25). Docs: `docs/analysis_redesign_plan_2026-10-19.md` sections 15-17, `docs/spectra_analysis_methods.md` (read before changing the maths), `docs/roi_shapes_and_linking_plan_2026-11-18.md` (ROI shapes, rims, sample / reference links, Type column), `docs/roi_position_tuning_2026-10-28.md` (Tuning tab, unseen by eye). Old analysis engine removed 2026-10-29; `analysis/tasks.compute_cell`, `provenance.py`, `reduction.py` are kept as the independent **reference implementation** the scan is checked against (inputs: `tools/reference_inputs.py`). Built but unused by the scan: fractional pixel weighting; `RoiToolbox.detect_rois` (tests only).

## Scan (analysis step 1) and what it stores

- **Bump `SCAN_ALGORITHM_VERSION` when a change can alter a stored number.**
- A change to what a cell depends on must keep "same hash => same numbers" (pinned on the numbers by `tests/unit/test_lspri_scan_local_mask_keys.py`). A new thing that makes one ROI's pixels depend on another ROI must be added to `frame_reduce.local_roi_keys`, and so to `ring_reach_matrix` (shared with `frame_reduce.build_subset_layout`). The cell hash falls back to the whole layout / whole mask when background removal uses the ROIs or masks in its estimate (`masks_are_global`), when there is no mask resolver, and for free-form ROIs.
- **Sample / reference ROIs (2026-11-18).** A reference ROI is scanned as one region (its pixels in the `SAMPLE` column, no ring, it loses the pixels of every sample ROI); which reference a sample is measured against is decided **afterwards on the stored numbers** (`analysis/reference_pairing.py`: linked references pooled by pixel, else the ring, else none), so a link or unlink makes nothing stale and needs no scan. **`ScanResultsModule.stored()` is the paired scan** (one row per sample ROI, reference ROIs have no row; with no reference ROI and no link it is the file's own object); the raw file is `_stored`, used by the staleness check only. The role is in the cell hash only for a reference ROI, so an all-sample session never rescans. **A list of ROIs that goes into a calculation (Spectra, Sensorgram, step table, groups, Signal map, S_bulk) is made with `RoiToolbox.sample_ids(ids)`**; a new consumer does the same. ROI position tuning never moves a reference ROI and refuses a sample that has links (it would score it against its moving ring; link-aware scoring is open, plan 1.2d); a linked reference never moves with its sample, only the built-in border does.
- **ROI shapes and borders (2026-11-18; plan "2 Shapes").** A ROI has `AreaRoi.shape` (`domain/roi_shapes.py`: `Circle` / `Rectangle` / `MaskShape`) and `AreaRoi.border` (`Border(gap, thickness)` = the pixels g .. g + t from the shape's edge; `None` follows `AreaRoiDetectionSettings.default_border()`, `NO_BORDER` has none). There are no loose diameter / geometry-type / mask fields any more: ask the shape (`reach_radius` / `nominal_diameter` when only a size is needed). **A circle's ring radii are computed in one place, `roi_shapes.ring_radii`**: the cell hash holds them as float64 bytes, so a one-ulp difference makes a cell stale without moving a pixel. Circle pixels, numbers and radii are pinned bit for bit against the code from before the change by `tests/unit/test_lspri_scan_circle_golden.py` (only its `golden_rois()` may change; a moved pin needs the maintainer). Rectangles and masks are found inside their own box (`roi/rasterize.py` `_region_hits`; the scan and the drawing use the same function) and take part in the neighbour test with their **reach** (`RoiSet.sample_r` / `ring_out_r` hold a reach, not a radius, for them: `roi_shapes.reach_radius`, `border_reach_radius`; plan step 2.2). Property tests in `tests/unit/test_lspri_roi_shape_reach.py` pin that no pixel falls outside a window box, read box or neighbour answer; a change to a shape's pixels or reach must keep them green. The toolbox's diameter commands (`resize_rois`, `reset_roi_diameters`, `refine_rois`, `place_array`) keep a diameter API for circles and refuse other shapes; **a change of the sample diameter alone carries the ring with it** (maintainer, 2026-11-18). A rotate / flip / crop turns a rectangle's angle (`remap_rectangle`). **A pixel mask is its pixels, not its centre** (the centre is only the label point): it is drawn and hit-tested from its pixels through the frame's affine (`shape_paths_item.placed`, `shape_hits`), and **it moves by whole pixels** (2026-11-19; `RoiToolbox._at_position`, the one rule behind a drag, a typed X / Y, a wheel step, a paste: the pixels shift by `whole_pixels(asked - centre)`, the label point by exactly the same, nothing is resampled; a move under half a pixel for every ROI of the call raises "it moves by whole pixels" instead of doing nothing; a drag keeps its own whole-pixel count for the maps, `RoiGestures._map_applied`, so small mouse steps are not lost; `MaskOutlines` remembers a map's traced outline by its pixels, not its place, so a dragged map is translated, not retraced: 44 -> 3 ms on 160 blobs). Session schema 1.12; a 1.11 file is read once through `_legacy_shape_and_border` (no other migration, maintainer: the app is in development).
- **Rim pairs, linked pairs, the Type column (2026-11-19; plan "Rim pairs, linked pairs, the Type column").** The user's word is **rim** (labels, tool tips, messages, undo labels); the code keeps `Border` / `border` and the saved keys. **Every blob of a pixel map has a rim of its own** (`rasterize._mask_band`: the union of the bands of the 8-connected blobs, each from its own edge, minus the other blobs' pixels; a one-blob map is unchanged; a many-blob map with a rim adds `|blob-rims` to its cell hash, so only it goes stale). `RoiToolbox.rims_to_references(ids, image_shape)` turns a sample's rim into a linked pixel-map reference (a frozen copy at the reference wavelength; the rim is taken where the sample is on the cube on screen (`cube=`: a drag on a later cube is a timeline change, not the base position), and the sample becomes a **rim-less ROI**, no dormant rim next to its reference: `turn_rim_off`, on every cube, its offset and thickness kept for `add_rim`; the switch is the ROI's, not a cube's, while the rim's size follows the scope rules; identical pixels at the reference wavelength, about 3 % of the edge pixels differ under a chromatic shift), `add_rim` gives a reference or a rim-less sample a rim; both are in the right-click ROI menu. The ROI table's column 7 is **Type**: `rows.icon_of` / `kind_of` decide the pictogram (a ring only while the ROI measures against its own rim) and the colour of its kind of pair (green rim or links, amber no reference, blue reference in use, gray reference unused; `type_icons.py`; the first column's dot keeps the ROI's colour); `row.shape` stays the editing key. The table's columns 5 and 6 are the rim's offset (header `d`, from the shape's edge, negative = inside) and thickness (header `w`), the same for circle, rectangle and pixel map (`rows.COLUMN_RIM_OFFSET / COLUMN_RIM_THICKNESS`, `has_cell`, `RoiToolbox.set_rim`; they were the circle's ring diameters d_r / D_r; a ROI with no rim, e.g. a reference, has blank cells).
- Links live on the sample (`AreaRoi.reference_roi_ids`); role / link rules: `domain/roi_links.py`; every command that renumbers or removes ROIs must carry them (`RoiToolbox._survivor_links`).
- Never remove the `stamped_by_previous_formula` recognition (`ScanStore.restamp`) without a migration: files from before would rescan every cube with a mask.
- The scan file's schema is `lspri_scan` 1.1 (it has the `n_masked` array the Sensorgram's mask marks read); an older scan file is replaced by a rescan.
- Finished cubes are written by `scan_store.ScanWriter` (a thread of its own), never by the thread that collects the workers' results (the pool is topped up only when that thread is back). The scan file holds plain (uncompressed) chunks; `write_batch` never writes a row outside its batch.
- `snapshot_source` runs on the GUI thread, everything else of a scan off-thread (`scan_jobs.py`). A partial read of an OME-Zarr export is bit-identical to a whole-plane read (`ScanSettings.partial_reads` switches it off). Known bottleneck, to be solved later (maintainer, 2026-10-27): the CRC32C check of every shard's index (cheaper ideas in the comment above `_SHARD_INDEX_CACHE_SHARDS` in `plane_reader.py`).
- Performance mode keeps a warm worker pool (~150 MB per idle worker); workers end by themselves when the app is gone (`scan._start_parent_watch`); a mode chosen during a scan applies after it.
- **Tools that build the app's modules (`tools/analysis_stage_timing.py` `build_modules`) must keep autosave suspended**: an edit made by a script was once saved into the real test session.

## ROI position tuning

- Accept copies the trial's numbers into `scan.h5` **bit-identical to a real scan of the moved ROIs** (pinned by a test): only when the trial's inputs are unchanged, only into a file that fits (`ScanStore.prepare(create=False)`), and not for ROIs next to another ROI or whose new centre is interpolated between lattice points. A trial scans the centre the toolbox stores (0.1 px rounding, `roi_tuning.moved_centre`).
- The *Tune toggle / pixel cache / preview* is designed but **shelved by the maintainer**: do not build it without a new go-ahead (`docs/single_roi_tuning_design_2026-10-28.md`).

## Analysis rules

*Principles that came from the removed engine (cut-over phase 2e, 2026-10-29). They hold for the scan too: nothing computes on selection or navigation, and a changed input makes a result stale, never silently wrong.*

- A scan runs **only** on explicit user action (Scan, Fast scan, ROI tuning Accept). Selecting ROIs or changing panels must never trigger computation; display reports "not yet analyzed".
- The recompute rule is deliberately simple: any change to a cell's inputs recomputes that cell. No materiality or pixel-selection comparison.
- Formula, Fit method, and Metric settings are **never** stored or put in provenance. They are recomputed live from RAM.
- One `scan.h5` per session (`analysis/scan_store.py`), plain uncompressed chunks; the cell hash decides what is stale.
- **Fractional pixel weighting (sketch section 6a) is partly built.** The raster (`roi/rasterize.py`, `rasterize_fractional`) and weighted reductions (`analysis/reduction.py`) exist and match unweighted results when weights are equal. **Not wired yet:** `analysis/tasks.py` `compute_cell` still calls the binary `rasterize_sample`/`rasterize_reference`.

## Testing

- Pure-computation files must import and test with **zero Qt, GUI, or dataset dependency**: `analysis/tasks.py`, `analysis/provenance.py`, `analysis/reduction.py`, `roi/rasterize.py`, `roi/detection.py`. A test of one of these that needs a `QApplication` means something is wired wrong. This is checked: contract `lspri-science-no-qt` in `.importlinter` lists the Qt-free modules (add a new pure one there; details: `docs/import_layering_2026-11-02.md`).
- A weighted reduction must match its unweighted counterpart exactly when all weights are equal.

## Pixel-index vs view coordinates (2026-11-18, half a pixel)

Everything stored and measured (the scan, the detectors, a ROI's stored centre = the table's X / Y, a mask's pixels, `RoiToolbox.display_positions`) is in **pixel-index** coordinates (pixel `(row, col)` is the point `(col, row)`); the canvas and the pointer are in **view** coordinates (the pixel covers `[col, col+1)`). The difference is `overlay_geometry.CELL_OFFSET` = 0.5, added once, after the affine. **Anything that draws a ROI or compares the pointer with one takes its centres from `RoiQueries.view_centers`, and a pointer position becomes a stored centre only through `RoiQueries.display_to_reference`** (a circle once sat half a pixel off the pixels it measured because it was drawn from the stored centre as it stood). A new overlay built from stored positions adds the shift itself. Record and numbers: `docs/roi_shapes_and_linking_plan_2026-11-18.md`, "Half-pixel fix".
